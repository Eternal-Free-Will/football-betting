# 定时任务处理

Mac 的系统权限非常严格，在 Mac 上运行命令，有两个隐藏的坑可能会导致脚本无法准时执行，为了确保万无一失，请检查以下细节：

1. 防止电脑休眠：
如果晚上 9 点你的 Mac 盖子合上了或者进入了深度休眠，任务是不会跑的。

方法 A： 保持电脑插电并打开盖子。

方法 B（推荐）： 安装一个叫 Amphetamine（安非他命） 的免费 App，或者在系统设置里勾选“当显示器关闭时防止自动进入休眠”。

2. 权限拦截（Mac 的 TCC 保护）

Mac 的系统安全性非常高，cron 程序默认可能没有权限在 /Users/freewill/Code/... 下创建文件夹或写入日志。

解决办法：

打开 系统设置 (System Settings) -> 隐私与安全性 (Privacy & Security)。

找到 完全磁盘访问权限 (Full Disk Access)。

点击底部的 + 号，按下 Command + Shift + G，输入 /usr/sbin/cron 并回车，将其添加进去并确保开关是开启状态。

同样的方法，确保你的 终端 (Terminal) /bin/sh 也在这个列表里。

必须添加的项目：

iTerm：点击 + 号在“应用程序”里找到并添加。

cron：点击 + 号，按 Command + Shift + G，输入 /usr/sbin/cron，添加并开启。

sh (可选但推荐)：按 Command + Shift + G，输入 /bin/sh，添加并开启。

3. 环境变量问题 (PATH)
虽然你写全了 Python 的路径，但如果你的脚本内部调用了其他系统命令，或者依赖某些特定的环境变量，cron 环境（它是一个非常纯净的 Shell）可能找不到它们。

建议改法：
在 crontab -e 的最顶端（第一行），加入一行 PATH 声明，这样更保险：

```
PATH=/usr/local/bin:/usr/bin:/bin:/usr/sbin:/sbin

40 10 * * * /Library/Frameworks/Python.framework/Versions/3.11/bin/python3 /Users/freewill/Code/football-betting/py_src/500.py >> /Users/freewill/Code/football-betting/py_src/cron_log.log 2>&1
```

## crontab

crontab -l 确认已生效

获取你的 Python 完整路径
which python3

设置定时任务
crontab -e

（这会打开一个编辑器，如果提示选编辑器，选 1 也就是 nano 比较简单）

按下 Ctrl + O 保存，再按 Enter，最后 Ctrl + X 退出。

如果系统弹窗询问“终端想要管理您的计算机”，请点击**“允许”或“确定”**

实时看日志：如果到了 9 点你想看进度，直接在 iTerm 输入：
tail -f /Users/freewill/Code/football-betting/py_src/cron_log.log

💡 专业技巧：命令行快速模式 (Caffeinate)
如果你不想改动系统长期的设置，只是想临时让 Mac 在某段时间内保持“清醒”，你可以在终端（iTerm）里输入这个简单的命令：

caffeinate -t 3600 &

caffeinate -t $((3600 * 3)) &

3600 代表 3600 秒（1小时）。

执行后，即使你合上盖子（插电状态），Mac 也会像喝了咖啡一样强制保持清醒。

由于你已经写了 crontab，上面的系统设置方法是最稳妥的，因为它是永久生效的。
